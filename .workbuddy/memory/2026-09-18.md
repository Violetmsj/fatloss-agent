### 补充：与 dg-piagent 作者《第 7 章》的对比

小马提供了作者原文 `第 7 章：准备上线——把 Agent 封装成一个服务.md`（项目根目录）。
作者列的四种接入方式（TUI / 打印 / RPC / 进程内嵌 SDK）**明确选了「进程内嵌 SDK」= 我的路线 C**，
把 RPC 归类为「宿主程序不是用 Node 写的才用」（Python/Go 后台），理由是避免多起子进程和多一层 IPC。
即：**我推荐的 B 不是作者的方案**。作者的架构 = Express + createAgentSession + session.subscribe → SSE，
单接口 `POST /chat` 响应即 SSE 流，事件翻译为 text/thinking/tool_start/tool_end/done/error，单用户（busy 标志）。

作者的 DataAgent 是「问答 + 工具」场景，**没有交互式问卷**，所以没碰到 ctx.ui 在自建宿主下失效的问题——
而这正是小马建档流程的核心。详见 MEMORY.md「建档问卷陷阱」。

修正后的建议：短期要最快在浏览器看到效果 → B；做长期产品 → 作者的 C 方案，但**建档必须前端化**。

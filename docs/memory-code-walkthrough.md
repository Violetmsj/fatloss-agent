# 长期记忆实现

## 从消息到回复

```text
DSH 会话追加事件
  → host/messages.ts 过滤来源、提取文本和稳定来源键
  → index.ts 的 fatloss:messages 会话投影
  → agent.ts 为每个减脂会话创建 MemoryCoordinator
  → 当前模型的独立请求提取候选
  → MemoryStore 校验证据与版本并事务写入
  → 下一步 systemPrompt.context 读取最新有效快照
```

[消息适配](../src/host/messages.ts)只接受真实用户、问卷回答和已提交助手文本；插件通知、系统提示词快照与工具结果不能成为用户证据。消息 ID 用于候选引用，来源键用于分叉去重；只有用户消息计入待处理轮数。

[记忆调度器](../src/core/memory-coordinator.ts)不导入宿主 SDK，通过函数获得消息、画像、空闲状态、模型提取与通知能力。回复结束且有十条待处理用户消息时提取；不足十条时等待空闲五分钟，新输入会取消空闲计时。每批最多处理十条用户发言，同时触发只发起一次请求。

[预设接线](../src/agent.ts)负责将 DSH 事件连接到调度器。每个 Agent 独立拥有调度器，释放时停止计时和在途请求；整个插件卸载再关闭共享数据库。模型请求通过 [host/runtime.ts](../src/host/runtime.ts) 使用当前请求模型，并采用独立辅助请求身份，不把后台请求作为主聊天的一轮。

## 存储和证据

[MemoryStore](../src/core/memory-store.ts)与画像、每日记录、报告共用插件 SQLite 连接。长期记忆不写入 Chroma。数据库路径由宿主显式传入，默认目录见根 README。

候选格式和提取提示词定义在 [memory.ts](../src/core/memory.ts)。候选必须包含允许的操作、类别及真实用户消息中的逐字原话，不能把助手建议、假设、他人情况或画像已有字段当作独立记忆。程序核对来源、结构、日期和版本；自然语言含义仍需由模型判断。

- 没有明确期限的阶段状态，默认从原话时间起七天失效；稳定偏好不默认过期。
- 更新和删除使用版本检查，冲突时整批回滚，防止后台旧快照覆盖较新的纠正。
- 空候选会推进处理进度，避免重复提取同一批消息。
- 失败、非法输出和超时不推进进度，在后续正常触发时重试，不自动无限循环。
- 停止或会话切换使在途结果失效；迟到结果不得写库。

## 工具与上下文

[记忆工具](../src/core/tools/memories.ts)统一注册查询、创建、更新、失效和删除能力。明确要求记住或纠正时，工具使用当前真实用户证据立即处理；一般陈述交由后台提取。

每步回复前读取有效记忆，而非长期缓存旧文本。DSH 的动态上下文会形成宿主快照，因此提示词明确当前有效快照优先。失效记录仍可查询，但不进入有效上下文；删除移除记忆正文及原话副本，并保留来源指纹防止旧来源重放。未来的新陈述仍可形成新记忆。

删除业务记忆不等于删除 DSH 原始聊天或历史上下文快照。

# 减脂报告

日报、周报、月报、年报和自定义报告使用独立固定模板。指标与图表数据由程序计算，AI 只生成末尾总结。所有报告保存到本机 `data/fatloss.sqlite` 的 `reports` 表。

## 使用方式

重启后端或 TUI，使新增工具生效，然后在聊天中提出请求，例如：

- “生成今天的日报。”
- “生成上周的周报。”
- “生成 2026 年 9 月的月报。”
- “生成 2025 年的年报。”
- “生成 2026-09-01 到 2026-10-10 的报告。”
- “查看我之前生成的月报。”
- “我补记了饮食，请更新 2026-09-01 的日报。”
- “请重试这份月报的 AI 总结。”

Web 聊天侧栏的“减脂报告”进入 `/reports`；生成工具卡片也提供“查看报告”链接。详情页可下载 Markdown、查看历史版本和过期提示。页面只负责查看，生成、更新和重试均通过聊天执行。

## 周期与统计口径

- 日期以 `Asia/Shanghai` 为准；周一至周日为自然周，月报与年报采用自然月、自然年。当前周期仅统计到今天，包含当天已落库的记录，标记“周期尚未结束”。
- 自定义区间包含起止日期，未来部分不参与统计，全未来范围拒绝生成。展示粒度依据所选完整跨度：不超过 31 天按日，32～120 天按自然周，更长范围按自然月；边界分组仅包含区间内日期。
- 周、月、年报直接聚合原始记录，不依赖较短周期报告。
- 日均摄入为饮食明细热量合计除以有饮食记录的日期数。饮食和运动覆盖分别统计，空的每日快照不算已记录日。
- 未记录保留为空，不能推断当天没有进食或运动。明确记录的零值保留为零。
- 营养素只汇总已知值，显示“已知条目 / 全部饮食条目”；全部未知不补零，部分未知标注“已知部分合计”。运动距离同样仅汇总已知值。
- BMR、TDEE 和摄入参考读取每天保存的历史快照，缺失时显示未知。分组平均摄入参考只使用有饮食记录且参考已知的日期，分母可能与日均摄入不同。
- 运动消耗单独呈现，不叠加到 TDEE。不计算达标率、实际能量缺口或减重预测。当前没有身体指标历史，因此没有体重或体脂变化曲线。

## 保存与更新

每个版本保存周期、截止日期、原始记录快照、统计 JSON、数据指纹、总结和 Markdown，以及生成时间、模型标识、数据结构和模板版本。

默认请求生成已有周期报告时直接复用。读取详情会比较原始记录与周期进度，变化时提示过期但不改写历史快照。明确更新后创建新版本；数据不变且总结已完成时仍复用原版本。

AI 总结状态为 `pending`、`complete`、`failed` 或 `not_applicable`。失败、超时和取消保留统计。明确重试时，若数据未变化则补齐原版本总结，若数据已变化则创建新版本。成功总结固定保存；没有饮食或运动明细的空报告不调用模型。

生成总结使用当前会话模型的独立请求，不附带聊天历史、原始食物明细或工具。请求最长 45 秒。SQLite 短事务与 60 秒租约防止相同版本被并发重复生成，进程中断后允许重试。

## 接口

模型工具：

| 工具 | 参数 |
| --- | --- |
| `generate_daily_report` | `date` |
| `generate_weekly_report` | `date`，周内任一日 |
| `generate_monthly_report` | `month`，格式 `YYYY-MM` |
| `generate_yearly_report` | `year`，整数年份 |
| `generate_custom_report` | `fromDate`、`toDate` |
| `list_reports` | 可选 `type`、`fromDate`、`toDate`、`page`、`pageSize` |
| `get_report` | `id` |

五个生成工具都支持可选 `regenerate`，默认 `false`，只有用户明确更新或重试时才使用 `true`。相对日期必须先单独获取当前时间。

只读 Web API：

- `GET /api/reports`：筛选已保存版本；日期筛选采用区间交集。默认第 1 页，每页 20 份，最大每页 50 份。
- `GET /api/reports/:id`：指定版本详情，包括原始快照、统计、总结、过期状态和同周期版本列表。
- `GET /api/reports/:id/markdown`：下载该版本已保存的 Markdown。

无效筛选返回 400，不存在的报告返回 404。报告 ID 只用于数据库查询，接口不接受文件路径。

## 验收

运行根项目与 Web 的类型检查、测试和构建命令。报告专项测试使用临时 SQLite 与假模型，覆盖周期边界、缺失值、版本保留、源数据变化、总结失败/取消/超时、租约恢复、并发去重、API 下载、独立模板及聊天链接恢复。

第一版不包含定时生成、独立 HTML/PDF 导出或新增身体指标记录。

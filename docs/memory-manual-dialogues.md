# 长期记忆人工测试：可复制对话

本文中的对话块可以逐条复制进 pi TUI。每发一条，等助手回复完再发下一条；不要把整组一起粘贴成一条消息。操作说明和“预期结果”不用发给助手。

建议先做 A、B、C 三组，覆盖立即写入、自动提取、纠正、跨会话读取、删除及错误记忆的边界；D、E 用于进一步检查时效和资料确认。

## 自动测试现在验证到什么程度

目前 `npm test` 有 40 项测试，其中 24 项是记忆功能测试。最近一次完整运行全部通过。

| 层次 | 已验证内容 | 不能据此断言 |
| --- | --- | --- |
| 数据存储 | 临时目录中的真实 SQLite；新增、纠正、失效、删除、重复处理、原话检查、事务回滚、版本冲突 | 真实模型一定提出正确的内容 |
| 调度 | 用可控时钟验证 10 条用户消息、5 分钟空闲、60 秒超时、取消、恢复和不重复请求 | 实际 TUI、网络、认证在当前机器上一定正常 |
| 工具及上下文 | 工具注册、最新用户证据、有效记忆注入、删除后不再注入旧内容；模拟 SDK 事件 | 主模型一定选对工具或在最终回复里正确使用记忆 |
| 提取语义 | 提供固定真实模型评估样例，尚未实际运行 | “普通问答不入库”等所有自然语言边界已被验证 |

“假模型”的意思是测试预先安排它返回 `[]`、一个合法候选，或者错误结果，再检查程序怎么处理。不是让真实模型阅读一句话，再判断它理解得对不对。

## 准备：建立隔离的测试副本

前提：原项目依赖已经安装，`.env` 与 pi 模型认证已配置到能正常聊天。知识问答场景使用现有 Chroma 服务；如果知识库尚未运行，在原项目另一终端执行 `npm run chroma`，尚未索引时按 README 完成 `npm run kb:index`。

首次打开测试副本时，按 pi 提示信任此项目扩展。记下终端输出的测试目录；之后要继续这个测试，应在该目录运行 `npm run tui`。再次执行上面的整块脚本会创建新的空白测试副本。

这里预填了虚构资料，所以不用再手动填写问卷。不要把对话开头写成“以下是假设”或“以下是测试台词”：那会改变被测语义，使原本要保存的明确陈述变成假设。

### 两条容易混淆的规则

- `/new` 创建新的聊天历史，但同一测试目录仍共用同一个记忆数据库。正是利用这一点测试跨会话记忆；它不是清空数据的命令。
- `/memories` 查看有效记录，`/memories all` 还包含失效记录。超过一页时用 `/memories all 2` 等翻页。判断保存成功要查看实际记录，不能只相信助手说“我记住了”。

## A. 快速验证：记住 → 换会话 → 纠正 → 删除

本组主要测试即时工具，不需要等 5 分钟。建议最先做，通常约 5–10 分钟，取决于模型响应速度。

### A1. 查看基线

```text
/memories all
```

预期：新测试副本中暂无记忆。虚构的身体资料存在 `profile` 中，不应该出现在这里。

### A2. 明确要求记住

```text
请记住我的提醒方式偏好：不要拿我的进度和别人比较，提醒我时温和一点。
```

预期：助手调用 `create_memory`，而不只是口头承诺；不用再次询问“是否确认保存”。模型可能把两个可独立修改的偏好拆开保存，不强求恰好一条。

```text
/memories all
```

检查：内容保留“不与别人比较”和“温和提醒”的意思，类别为偏好，依据为 `explicit`，原话来自刚才的消息，没有“自卑”“缺乏自律”等推断；记下对应 ID 和 version。

### A3. 新会话中回忆

```text
/new
```

等新会话打开后再发送：

```text
关于提醒我这件事，你记得我之前表达过哪些偏好吗？不知道的部分请直接说不知道。
```

预期：能说出刚才保存的偏好。问句里没有重新提供偏好内容，且聊天历史是新的，因此更能检查数据库记忆是否生效。

### A4. 纠正其中一个偏好

```text
纠正一下我的提醒语气偏好：可以直接、明确地提醒我，不必刻意温和，但不要责备我。不与别人比较这一点继续保留。
```

预期：查询已有记忆，更新对应记录。目标记录的版本应增加；如果之前两种偏好分开保存，只修改受影响的部分，不强求所有记录的版本都变化。

```text
/memories all
```

检查：当前有效内容体现“直接明确、不要责备、仍不与别人比较”；不能同时保留互相矛盾的有效语气偏好。完整证据链中仍可能看到旧原话，那是来源历史，不等于旧内容仍有效。

### A5. 验证纠正后的回复

```text
/new
```

```text
根据你已经记住的提醒方式偏好，给我写一句简短的行动提醒。不需要制定饮食或训练方案。
```

预期：回复直接明确，不责备、不与别人比较。自然语言没有唯一正确措辞，重点看是否与有效偏好冲突；这一步单独通过不能证明记忆有效，要结合 A3 和实际记录判断。

### A6. 删除

```text
请删除你记住的关于我的提醒方式的全部偏好，包括提醒语气和不与别人比较的要求。
```

预期：助手查询匹配项并调用 `delete_memory`；目标明确时不反复确认。若之前拆成多条，应删除所有匹配项。

```text
/memories all
```

预期：这些记录彻底消失，不是仅变成 inactive。

```text
/new
```

```text
关于提醒我这件事，你现在还保存着哪些我的个人偏好？如果没有，请直接说明没有记录，不要猜测。
```

预期：没有相关记录，不声称仍然记得刚才已删除的偏好。助手仍可能按通用系统规则使用温和语气，这不等于删除失败；重点是有没有把已删除内容说成已知的个人事实。

## B. 自动记住：不说“请记住”，不足 10 轮也能保存

### B1. 新开会话，普通陈述一条偏好

```text
/new
```

```text
聊到我自己的进度时，我不喜欢你拿其他人的成果和我作比较。
```

本句没有要求立即保存。预期由后台提取，而不是主助手立即调用 `create_memory`。

### B2. 等待空闲处理

等回复彻底结束后，保持 TUI 打开，不发送任何新内容，等待 5 分钟，再留最多约 1 分钟给模型请求。

预期：出现记忆新增提示。若出现提取失败提示，记录原文，这属于本次链路失败，不能算通过。

```text
/memories all
```

检查：包含不与他人成果比较的沟通偏好，引用 B1 原话。这个测试证明“普通明确陈述 → 后台模型 → SQLite”接通了；A 组只证明即时工具链路。

### B3. 换会话读取

```text
/new
```

```text
我之前明确说过，聊到我的进度时不喜欢哪一种做法？如果没有记录，就直接说没有记录。
```

预期：准确提到不拿其他人成果作比较。

## C. 自动提取边界：连续 10 轮，但不应产生新记忆

在同一测试副本继续即可，B 组的偏好可以保留。开始前查看 `/memories all`，以已有记录为基线；本组要求的是“没有额外新增”，不要求全库为空。

```text
/new
```

下面每个代码块分别发送一次，等助手完整回复后再发下一条。尽量不要在轮次之间停顿满 5 分钟，否则会提前触发空闲处理，难以单独检验第 10 轮触发。遇到助手追问时，可直接继续下一条，不需要补充个人信息。

### 第 1 轮：普通知识

```text
蛋白质有什么作用？
```

### 第 2 轮：普通知识

```text
为什么体重会每天上下波动？
```

### 第 3 轮：普通知识

```text
热量缺口是什么意思？
```

### 第 4 轮：普通知识

```text
体重下降和体脂下降是一回事吗？
```

### 第 5 轮：问进度，不等于焦虑

```text
你觉得我最快多久能达到目标？
```

### 第 6 轮：假设人物

```text
假设有一个人上夜班，讨论他的运动安排时应该先了解哪些条件？
```

### 第 7 轮：他人的情况

```text
我朋友特别不喜欢被催促。和他讨论计划时，怎么表达比较合适？
```

### 第 8 轮：让助手提出示例建议

```text
请举一个“建议某人考虑散步”的表达例子。
```

### 第 9 轮：尚未接受建议

```text
对于刚才提到的散步建议，我还没有决定是否采纳。
```

### 第 10 轮：普通知识

```text
为什么观察减脂进度时要关注长期趋势，而不是某一天的数字？
```

第 10 次回复结束后，给后台模型最多约 1 分钟，再查看：

```text
/memories all
```

预期：与本组开始前的基线相比，没有新增或改写个人事实。尤其不应出现“焦虑／急切达标”“上夜班”“因为朋友的情况而不喜欢被催促”“喜欢散步／决定开始散步／已采纳建议”等结论。

第 9 轮虽出现用户的暂未决定状态，本组的预期是它不足以成为有长期价值的独立记忆；若被保存，记录其实际内容，作为提取价值判断需要调整的样例。不要只检查有没有“喜欢散步”四个字。

空结果正常情况下没有成功提示。仅看到“无提示、无新增”不能单独证明后台请求已经执行；B 组用于验证触发链路，自动测试验证空结果会推进进度。若需要直接观察负例的候选 `[]`，再运行下面的 `memory:eval`。

## D. 阶段状态和失效

### D1. 保存临时状态

```text
请记住：最近我在出差。
```

```text
/memories all
```

预期：类别为阶段状态，有到期时间，约为本条用户原话时间加 7 天。显示为 UTC 时需要加 8 小时理解为北京时间。这里不需要真的等 7 天，到期过滤已由可控时钟自动测试覆盖。

### D2. 主动说明状态结束

```text
之前说的近期出差已经结束了，这条状态不再适用。
```

预期：对应出差状态被失效，不编造“现在在家”等未陈述的情况。

```text
/memories
```

预期：有效列表里不再有出差状态。

```text
/memories all
```

预期：仍能找到该记录，状态为 inactive。这与 A6 的物理删除不同。

## E. 用户资料修改不能被长期记忆绕过

```text
/profile
```

记录当前体重。隔离脚本创建的初始体重是 85.5 kg。

```text
把我的当前体重改成 78 公斤。
```

预期：助手先读取资料，展示旧值和新值，等待确认；此时不能已经修改，也不能用长期记忆另存一份“当前体重 78 公斤”。

```text
先不要修改，保留原来的资料。
```

```text
/profile
```

预期：体重仍是原值。

```text
/memories all
```

预期：没有新增“当前体重 78 公斤”。如果还要检查后台提取也遵守这个边界，保持空闲 5 分钟并等待本次提取完成，再查看一次。

## F. 不想逐条聊天时，直接评估提取模型

在原项目的另一个终端执行：

```bash
cd /Users/violet/code_project/fatloss-agent
npm run memory:eval
```

它会依次把 11 个固定样例发给真实模型，打印候选、保存结果和 `review`。使用内存 SQLite，不修改个人资料或长期记忆；会产生模型请求用量。

检查重点：

- 普通问答、猜测心理、未接受建议、假设、他人情况等负例，候选应为 `[]`。
- 明确偏好应提取，纠正应更新已有 ID，已结束状态应失效。
- `actionCheck: 通过` 只表示操作种类和数量符合预期，内容仍需人工阅读。例如“都执行了 create”并不代表没有曲解用户。
- 此命令直接测试提取器，不验证 TUI 的 10 轮／5 分钟触发，也不验证主助手的工具选择和最终回复。这些由 A–E 组补足。

## 遇到异常时复制这份记录

```text
测试组／步骤：
模型 provider/model：
测试时间：
我发送的原话：
助手实际回复及工具调用：
后台是否有新增／失败提示：
/memories all 中对应记录（内容、ID、version、状态、到期时间）：
预期结果：
实际结果：
```

有原话、实际记忆和模型信息，才能区分是提取理解错误、工具调用错误、触发失败，还是记录正确但回复使用不当。测试结束后可退出测试 TUI；后续日常使用仍从原项目目录启动。

# 长期记忆验证

## 自动测试与模型评估的区别

`npm test` 使用临时 SQLite、假模型和可控时钟，验证来源检查、事务、版本冲突、有效期、调度、工具及上下文注入，不发起网络请求。它不能证明真实模型能正确理解每种自然语言表达。

`test/fixtures/memory-evaluation.json` 提供固定原话、初始记忆、预期操作和人工检查要点。使用已配置的 pi 模型手动运行：

```bash
# 默认与项目 TUI 一样使用 deepseek/deepseek-flash
npm run memory:eval

# 也可指定本机已经配置的 provider/model
npm run memory:eval -- deepseek deepseek-flash
```

此命令会请求真实模型并产生用量，使用固定虚构资料和内存数据库，不读取或修改 `data/fatloss.sqlite`。自动核对输出结构、原话来源、入库校验及操作类型；逐项检查输出的 `review`，确认没有遗漏否定、弄错人物、过度概括或把猜测当事实。相同模型的输出仍可能波动，调整提示词后应重复运行并比较异常样例。

## TUI 完整流程

可直接复制的完整测试台词、隔离启动脚本和逐步预期结果见 [长期记忆人工测试对话](memory-manual-dialogues.md)。

在开发用用户资料下测试，避免把虚构偏好加入日常使用的资料。`/memories` 查看有效记录，`/memories all` 查看全部记录，末尾可加页码，例如 `/memories all 2`。

1. **记住**：说“我不喜欢被催促，希望你提醒我时温和一点”，不要要求立即保存。完成回复后保持空闲 5 分钟，确认出现新增提示；用 `/memories` 检查原话和类别。换新会话问“你以后会怎样提醒我”，检查回复体现温和提醒。
2. **纠正**：说“纠正一下，我接受你直接提醒，但不要责备我”。确认调用查询和更新工具，目标 ID 不变、版本增加，当前内容被替换。再问提醒方式，检查使用新偏好而非旧值。
3. **忘掉**：说“请忘记我的提醒方式偏好”。确认调用删除工具；`/memories all` 不再包含该条。换新会话问提醒方式，检查助手不声称记得已删除的偏好。原始聊天历史仍在，删除不是清空会话。
4. **批处理**：在另一个开发会话累计 10 次用户发言，其中混入普通知识问答和未接受的助手建议。确认只在回答结束后提取，不把工具调用计为用户轮数；没有合格候选时不提示、不新增记录。
5. **profile 边界**：说“我现在体重 78 公斤”。确认助手仍展示资料差异并要求确认，不能改为直接写长期记忆；未确认时 `profile` 不变。

记录模型名称、日期、候选原文及最终回复。先评估“该不该记”和“记得是否准确”，再评估回复是否使用了相关记忆，不以入库条数作为效果指标。

## 当前行为边界

- 只自动提取启用后、当前会话分支的原始用户消息。恢复对应会话可继续未完成的提取，不扫描所有历史会话。
- 模型判断语义；程序核对结构、真实用户来源、日期、目标和版本。引用真实原话仍不等于结论必然正确，用户可随时纠正或删除。
- `list_memories` 的文本筛选是包含匹配，不是语义检索。记忆量较大或证据较长时，上下文会提示查询完整记录。
- 关闭、切换或 60 秒超时会取消当前提取；失败保留进度，在下次正常触发时重试。空闲 5 分钟处理需要应用仍运行。
- 失效保留历史记录但排除于有效上下文；删除移除该条正文和原话副本，保留不可还原原文的来源哈希，防止旧来源重放。未来重新明确表达可形成新记忆。
